**Figures are the median across repeated full runs**, not a single run. This machine has no thread pinning available, and between-run variance is larger than the within-run sample spread: across the runs merged here the median row moves ~1%, but the worst rows move up to ~12%. Each row in the CSV carries its own `spread_pct` so any quoted number comes with its reliability. Differences below roughly 5% should not be read as real.

*KleidiAI 8VS uses a 16x16 tile against everyone else's 1024-element tile, so it is not doing the same work per invocation.*

> **Stability caveat for this experiment.** Across repeated runs the MaxMulSK rows and Accelerate reproduce to within +/-1.5%, but the KleidiAI rows in the hot-micro-kernel harness swing 5-9% (and KAI 8VS at Kc=128 by more than 70%). Its entry point does smstart/smstop per call, which this harness exercises far more often than any real GEMM does. Treat a 1x4Acc-vs-KleidiAI hot ratio near 1.0 as a tie, not a win; the end-to-end and prepacked rows below are stable for both sides.
