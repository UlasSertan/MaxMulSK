# Benchmark result archive

One directory per measurement session, named by date. **Nothing here is ever
deleted or overwritten** — a superseded run stays, because the progression is
part of the record and because a later run that disagrees is only interpretable
next to the earlier one.

Each directory holds the raw outputs plus a generated `SUMMARY.md`. What matters
when reading them is *which code state produced them*:

| Directory | Code state | Notes |
|---|---|---|
| `2026-09-05/` | 1x4-Acc with **SVE butterfly** pack_A, row-major ZA→C store | Single run. Superseded by 2026-09-06 for the Acc kernels; every other implementation is unchanged between the two. |
| `2026-09-06/` | 1x4-Acc with **ZA-transpose** pack_A (current) | Median of three full runs (`maxmul_vs_kleidiai_avg.csv`). **Use this one.** |

## Files in a session directory

| File | Contents |
|---|---|
| `SUMMARY.md` | Consolidated tables, generated by `bench/grand_summary.py` |
| `environment.txt` | Hardware, compiler, and the exact version of every third-party thing measured |
| `maxmul_vs_kleidiai.csv` | Layered benchmark, machine-readable. Run 1. |
| `maxmul_vs_kleidiai_run{2,3}.csv` | Repeat runs, when the session did them |
| `maxmul_vs_kleidiai_avg.csv` | Median across runs, plus a `spread_pct` column per row |
| `bench_compare.txt` | The repo's original comparison table |
| `python_baselines.txt` | NumPy and PyTorch, single-thread |
| `energy.txt`, `energy.csv` | Power and J/GFLOP, when the energy step was run |
| `build.log` | Build output. Non-empty errors here invalidate the whole directory. |

## Reproducing

```
./bench/grand_benchmark.sh                 # everything except energy
./bench/grand_benchmark.sh --power-only    # energy only, reusing an existing directory
./bench/energy_bench.sh                    # energy on its own
python3 bench/average_runs.py out.csv in1.csv in2.csv in3.csv
```

## Why repeated runs

This machine offers no thread pinning, and between-run variance turned out to be
materially larger than the within-run sample spread. Across the three runs merged
into `2026-09-06/`, the median row moves about 1% but the worst rows move up to
12%. Single-run figures are therefore not quotable on their own; `spread_pct` in
the averaged CSV carries the per-row reliability. **Differences below roughly 5%
should not be read as real.**

One further caution, learned the hard way: a build failure in an ad-hoc run can
leave a stale binary in place, and the benchmark will then happily measure the
*previous* code. `grand_benchmark.sh` checks the build's exit status and aborts;
`build.log` in each directory is the receipt. Check it before trusting a
directory.

## Raw powermetrics captures

`energy_bench.sh` writes one `.raw` capture per (implementation, shape) under
`<date>/energy_raw/`. These are the sampler's own dumps, not the measurement —
the measurement is `energy.csv`. They are stored gzipped (`.raw.gz`, ~10x
smaller); read one with `gzcat`. Nothing is deleted, here or anywhere else in
this directory.
